# OWN ENVIRONMENT PROBES (goal 4.4). The feed samples the PLAYER'S probe atlas, which is

# Most expensive feature on the roadmap: a probe update is six cube faces of scene geometry,
# and CPU submit is this route's bottleneck. Watch ourDraw and VRAM, not just fps.
# DISARMED 2026-07-30 18:46 AFTER A CTD. The fix is IN: the bootstrap now carries
# RttBridge.ParkedProbeManagers[] and the logic adopts the parked manager on every hot
# reload instead of building a fresh one beside it. The new bootstrap is ON DISK
# (deployed 21:40) but a bootstrap only loads at game start — so:
#
#   AFTER THE NEXT GAME RESTART, set this to 1.
#
# The log then says which world you are in: "bootstrap park found" (fixed) vs "NO
# bootstrap park (bootstrap predates it)" (old leak profile — one RTV set per reload,
# do not run own-probes through repeated hot reloads on that).

#   Assertion Failure: Out of the descriptor heap

#     at EnvironmentProbeManager.PrepareProbes_Patch1()

# How many INDEPENDENT feeds are active. 1 = everything as before.
#
# Each feed owns its own camera, ScreenBuffers, DrawContextManager, cascade set, LDR ring,
# panel binding and gate. They take turns: at most one renders per engine frame, strict
# rotation, so raising this divides feed fps rather than multiplying engine cost.
#
# WHICH PANEL GETS WHICH FEED IS EXPLICIT, from the tag on the block name:
#
#     [RTC]  or [RTC1]   -> feed 0
#     [RTC2]             -> feed 1
#     [RTC3]             -> feed 2        ... i.e. [RTCn] -> feed n-1
#
# Deliberately not "whichever panel ticks first": tick order belongs to the engine, so
# discovery-order assignment could swap the two panels between sessions — and a swapped
# assignment looks exactly like a routing bug. Naming the feed on the block makes it stable
# and readable off the panel itself.
#
# A panel asking for a feed beyond feedCount SHARES feed 0 and says so in the log, rather
# than silently mirroring.
#
# COSTS A GATE CYCLE. This IS in the rebuild signature, and the first attempt had it the
# other way round on the reasoning "adding a feed should not drag the others through a
# rebuild". That is wrong: changing this changes WHICH PANEL EACH FEED OWNS, and every feed
# caches its panel's identity (resolved id, offscreen target, the handle text the handover
# matches on). Re-routing under those caches leaves each feed matching another panel's
# handle — observed 2026-07-30 as a frozen picture with drawOne(ours)=0.0, correct routing
# in the log, and no error anywhere. The rebuild is what clears them.
feedCount = 1


# --- the VRAM admission cap (phase E1) ---------------------------------------
#
# feedCount is what you ASK for. These decide what you GET.
#
# WHY IT EXISTS: two feeds at 1024 SSAA were run on 2026-07-30 and the game device-removed
# 40 seconds later, with UsedVRAM at 13.70 GB against a 13.61 GB budget. Nothing noticed.
# The analytic resource walk then measured a feed at 384.7 MiB — so "does the next feed
# fit" is arithmetic that can be done BEFORE building it. Every 2 s the mod reads used and
# available VRAM, subtracts the reserve, divides by the measured per-feed cost, and clamps
# feedCount to what is left.
#
# THIS IS THE ONLY AUTOMATIC THROTTLE IN THE MOD, on purpose. Quality settings are a manual
# lever and stay one; the single thing the mod decides on its own is how many feeds it will
# hold at once.
#
# It never tears down a feed that is already running — it only refuses to admit a new one.
# Lowering the cap is immediate; raising it needs three consecutive polls to agree, because
# VRAM swings +/-200 MB frame to frame and a flapping cap would rebuild on every swing.
#
# Watch for "FEED VRAM CAP:" in rtt.log. It says loudly when it is clamping.

# Hard ceiling regardless of memory. Set 1 to pin single-feed behaviour permanently.
maxResidentFeeds = 4

# Headroom held back from the arithmetic. 512 because the fatal run was only ~90 MB over
# budget while VRAM noise alone is +/-200 MB — the margin between "tight" and "dead" is
# smaller than the noise, so the reserve has to clear both.
feedVramReserveMb = 512

# 0 = never consult VRAM, trust maxResidentFeeds alone. The escape hatch if the cap ever
# refuses a feed that would have been fine.
feedVramGuard = 1
